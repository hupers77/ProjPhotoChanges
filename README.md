# 포토웍스 웹 (photoWORKS 웹 버전)

사진 여러 장을 한 번에 크기 조정하고 서명과 사진 정보(EXIF)를 얹어 개별 파일로 저장하는 브라우저 앱입니다.
사진은 서버로 올라가지 않고 브라우저 안에서만 처리됩니다. 빌드 과정 없이 정적 파일만으로 동작합니다.

## 실행 방법 (맥)

처음 한 번 저장소를 받습니다.

```
cd ~
git clone https://github.com/hupers77/ProjPhotoChanges.git projphotochanges
cd projphotochanges
```

이후에는 이 폴더에서 아래를 실행하고 Chrome으로 http://localhost:8000 을 여세요.
최신 코드는 `git pull`로 받습니다.

```
python3 -m http.server 8000
```

ES 모듈을 쓰기 때문에 `index.html`을 더블클릭(file://)하면 열리지 않습니다.

## 인터넷 주소로 쓰기 (GitHub Pages)

설치 없이 https://hupers77.github.io/ProjPhotoChanges/ 에서 바로 쓸 수 있습니다. 처음 한 번만 켜 주세요.

1. GitHub 저장소 → **Settings** → 왼쪽 **Pages**
2. **Build and deployment**의 Source를 **Deploy from a branch**로 두고, Branch를 **main** / **/ (root)** 로 고른 뒤 **Save**
3. 1~2분 뒤 위 주소가 열립니다. 이후 main에 올라가는 변경은 자동으로 반영됩니다.

사진은 이 주소에서도 서버로 올라가지 않고 브라우저 안에서만 처리됩니다.
주소마다 브라우저 저장 공간이 따로라서, localhost에서 만든 프리셋은 **파일로 내보내기 → 가져오기**로 옮기세요.

## 지금 되는 것 (1단계)

- 사진·폴더 끌어다 놓기, 사진 선택, 폴더 선택 (하위 폴더 포함)
- 크기 조정: 긴 변, 짧은 변, 가로, 세로, 가로×세로 상자 안에 맞추기, 비율(%), 원본 유지 / 확대 방지
- 저장 형식: 원본과 같게, JPEG, PNG, WebP, 화질(50~100)
- 파일 이름 규칙: `{원본}` `{순번}` `{순번3}` `{순번4}` `{날짜}` `{시간}` (날짜·시간은 촬영일시, 없으면 파일 날짜)
- 저장: Chrome·Edge는 고른 폴더에 개별 파일로 바로 저장(같은 이름은 덮어쓰지 않고 ` (1)` 붙임),
  Safari·Firefox는 한 장씩 개별 다운로드
- 사진 방향(EXIF Orientation)은 자동으로 바로 세워서 저장
- 설정은 이 브라우저에 기억됨

## 2단계: 서명과 사진 정보

- 미리보기: 목록에서 누른 사진이 저장될 모습 그대로(크기·서명·EXIF 글자) 보이고, 설정을 바꾸면 바로 바뀜
- 서명: 글자 또는 이미지(투명 PNG 권장). 위치 9곳, 크기, 글꼴(고딕/명조/고정폭), 굵게, 색, 효과(그림자/테두리/배경 상자), 불투명도, 여백.
  서명 이미지는 브라우저에 기억됨
- 사진 정보 넣기: 문구 안에 토큰을 넣으면 사진마다 값이 채워짐. 값이 없는 항목은 구분자(`·` `|` `,`)와 함께 빠짐
  - `{카메라}` `{렌즈}` `{초점거리}` `{35mm환산}` `{조리개}` `{셔터}` `{ISO}` `{노출보정}`
  - `{촬영일}` `{촬영시각}` `{촬영일시}` `{작가}` `{저작권}` `{파일명}` `{제조사}` `{모델}`
  - 서명 문구에도 같은 토큰을 쓸 수 있음 (예: `© {작가}`)
- 크기는 사진의 짧은 변 대비 %라서, 사진 크기가 달라도 같은 비율로 찍힘. 서명과 EXIF를 같은 위치에 두면 겹치지 않고 위아래로 쌓임
- 원본 EXIF 유지(JPEG 저장 시): 촬영 정보가 그대로 남고, 방향은 바로 세운 값으로, 픽셀 크기는 새 크기로 고침.
  옛 썸네일은 빼고, GPS 위치는 기본으로 지움(끌 수 있음)

## 3단계: 프리셋과 속도

- 프리셋: 지금 설정(크기·서명·EXIF·저장 형식·파일 이름·저장 위치)을 이름 붙여 저장하고, 목록에서 고르면 바로 적용.
  서명 이미지도 함께 저장됨. 삭제, 기본값으로 되돌리기
- 프리셋 파일로 내보내기/가져오기 (`photoworks-presets.json`): 다른 브라우저·컴퓨터나 GitHub Pages 주소로 옮길 때
- 백그라운드 병렬 처리: CPU 코어 수에 맞춰 최대 4장을 동시에 Web Worker에서 변환. 처리 중에도 화면이 멈추지 않음.
  저장은 여전히 목록 순서대로 한 장씩. 백그라운드에서 못 여는 사진(예: Safari의 HEIC)은 화면에서 다시 처리
- 썸네일도 백그라운드에서 만들고, 변환이 시작되면 변환을 먼저 처리
- 완료 시 걸린 시간 표시

## 구조

| 파일 | 역할 |
|---|---|
| `js/settings.js` | 모든 설정을 담는 객체, 기본값, 저장/불러오기 (프리셋이 이 객체를 통째로 저장) |
| `js/resize.js` | 목표 크기 계산, 단계적 축소로 고화질 리사이즈 |
| `js/pipeline.js` | 사진 1장 처리: 디코드 → 리사이즈 → 오버레이 → 인코딩 → EXIF 넣기. 미리보기 렌더링 |
| `js/exif.js` | JPEG EXIF 읽기, 토큰 값 만들기, 출력용 EXIF 고치기(방향·크기·썸네일·GPS) |
| `js/overlay.js` | 서명·EXIF 글자 그리기, 위치 배치 |
| `js/filename.js` | 파일 이름 규칙 |
| `js/exporter.js` | 폴더 저장 / 개별 다운로드 |
| `js/presets.js` | 프리셋 저장/삭제, 파일 내보내기/가져오기 |
| `js/pool.js` | 백그라운드 작업자(Web Worker) 묶음, 우선순위 대기열 |
| `js/worker.js` | 작업자 안에서 `pipeline.js`로 사진 변환, 썸네일 생성 |
| `js/main.js` | 화면 연결 |

## 알려진 한계

- EXIF는 JPEG 원본에서만 읽고, JPEG로 저장할 때만 남음 (PNG·WebP 저장 시 빠짐)
- 색 프로필(ICC)은 옮기지 않음. 브라우저가 sRGB로 바꿔 그리므로 결과는 sRGB 기준
- HEIC는 Safari에서만 열림 (Chrome은 브라우저가 HEIC를 지원하지 않음)
